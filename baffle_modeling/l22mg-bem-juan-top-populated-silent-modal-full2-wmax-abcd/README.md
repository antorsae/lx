# LX521.4 L22MG baffle simulation

This is the current automated workflow for SEAS/LINKWITZ L22MG mounted as the only active source in the LX521.4 top baffle.

## A/B/C/D Wmax Shoulder Sweep

Only the symmetric LX521 `Wmax` shoulder point is moved; the L22 cutout, neck, top, bottom, passive locations, source fit, target, IR peak policy, and validation angle grid are unchanged.

These dimensions are provenance for H1659-derived approximations, not raw-STL acceptance evidence.

- Mesh handoff: 4885 vertices, 8204 triangles at h=6.5 mm using `delaunay`; lambda(1200 Hz)=285.8 mm; lambda/6=47.6 mm, lambda/10=28.6 mm.
- Mesh area check: front 0.08091 m2, analytic solid face 0.07223 m2 (front/side area includes added passive UM driver face and passive tweeter driver faces; analytic solid face is baffle only).
- BEM mesh quality: edge median 19.799 mm, p95 33.254 mm, max 39.830 mm; min triangle angle 14.052 deg (p01 14.052 deg); max edge ratio 4.083.
- BEM acoustic mesh: method `delaunay-local`, h=42.0 mm, quadrature order=7, max panels=4000, analytic source normal derivative. Adaptive controls: boundary h=28.0 mm, local h=28.0 mm, local refinement width=90.0 mm, feature clearance=0.25x local spacing. Near-panel quadrature: q7, subdivisions=1, distance factor=2.50. Target-panel normal-trace averaging: q7, chunk size=128. Linear solver: dense direct LU solve; max relative residual=1.567e-15 at 476.2 Hz (RMS relative residual=1.280e-15). - Canonical BEM check: `scripts/validate_dense_bem.py` validates the same dense Neumann matrix against analytic rigid-sphere scattering; latest generated report is `docs/l22mg-baffle-bem-canonical/README.md`.

- Solver upgrade path: `docs/l22mg-bem-upgrade-path/README.md` tracks the non-ad-hoc path: feature-preserving remesh, local hp refinement, and FMM/H-matrix or higher-order BEM before detailed STL acceptance claims.

## Known limits

- Validation alignment uses only one scalar gain and one delay.
- The default BEM source term is an equivalent source fitted from nude polars; source-surface coupling around the real L22 frame/flange is not explicitly modeled.
- `--source-model axisymmetric-directivity` rotates Juan's measured naked angular field into a directivity table and propagates it from the measurement radius. It is a no-inversion source diagnostic, not proof that Juan's horizontal polar uniquely determines Andres' off-plane incident field.
- `--bem-active-piston-source` switches to a flat prescribed-Neumann source disk. Its default strength follows Juan on-axis only and does not fit Juan polar directivity, so it is a source-surface diagnostic rather than an acceptance-grade driver model.
- `--source-model active-surface-modal` switches to a Juan-fitted H1659-shaped prescribed-Neumann source surface. It is a stronger driver-surface diagnostic, but it is still an open rigid acoustic surface, not coupled elastic cone/suspension physics.
- `--source-model split-active-surface-modal` fits independent front/rear H1659-shaped prescribed-Neumann source surfaces to Juan only. The side gap is a source-model discretization parameter, not an Andres-derived correction.
- Legendre BEM runs use a far-field angular model as a near-field multipole expansion; discrete-source BEM runs bound that near field, split-discrete runs separate front/rear components, and split-ring runs expand circular source rings.
- `--include-driver-face` adds a simple rigid surface-mounted annulus, but it is still not a detailed basket/cone/flange model.
- `--include-driver-stl-envelope` uses only a coarse revolved radius envelope from the driver STL for diagnostic obstruction sensitivity. It is not a raw-STL solve, not feature-preserving remeshing, and not an acceptance-grade model.
- `--include-driver-frame` adds a coarse feature-aware rigid frame/basket/motor obstruction from H1659 STL dimensions. `--driver-frame-include-mounting-holes` optionally cuts the STL-derived screw pockets into that flange, but the path still omits cone/surround compliance, elastic coupling, and feature-preserving STL remeshing.
- `--active-driver-feature-proxy` explicitly requests the H1659 acoustic feature-proxy path: rigid frame/flange/motor geometry plus a Juan-fitted prescribed-Neumann acoustic surface, with mounting pockets forced on. Combining `--include-driver-frame` with an active-surface source remains labelled as the same proxy path for legacy runs. The 0.6 mm flange sidewalls default off for this path as an explicit mesh-quality approximation; pass `--driver-frame-include-front-flange-sidewalls` to include them. It is not a scalar correction, not fitted to Andres, not a raw-STL dense solve, and not elastic FEM-BEM.
- Runtime note: the dense BEM cost is dominated by matrix assembly and O(N^3) linear solves per frequency. A Rust rewrite is not the first lever unless profiling shows Python overhead dominates; better mesh sizing, iterative solvers, or an accelerated BEM backend matter more.
- Linear-solver note: `--bem-linear-solver gmres` is an audit/control path in this dense backend. `gmres-matrix-free` avoids storing the dense matrix for targeted larger diagnostics, but it is still an O(N^2) dense-kernel matvec, not FMM-BEM or H-matrix acceleration, and it does not change the source model or validation alignment.
- Acoustic-center note: the automatic phase scan is conservative and falls back to 0 mm when the best fit lands on the +/-40 mm search boundary; use `--acoustic-center-offset-mm` for an explicit nonzero offset study.
- Mesh note: `delaunay-adaptive` keeps the interior at the requested h while sampling the outside edge, cutout, passive holes, and thickness walls at h/2. `delaunay-local` adds a finer point field only near baffle features, and `--bem-auto-mesh` derives broad/local spacings from wavelength plus baffle/cutout feature dimensions.
- Edge fallback strengths are fixed baseline coefficients, not fitted to Andres.
- True BEM acoustic mesh convergence is proven only when a BEM mesh sweep is run and compared; the fallback convergence table checks edge/cutout sampling density only.
